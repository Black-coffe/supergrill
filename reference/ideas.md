# Lens: ideas — raw idea validation & research

Goal: answer ONE question — is this idea worth pursuing at all — as cheaply as possible. This lens both interrogates AND researches: you actively search for prior art and evidence, not just ask. Default level: `deep` (research needs web access); `quick` only when the user wants a gut-check.

## Two hats, alternating

- **Interrogator:** grills the user about the idea (tracks below).
- **Researcher:** during recon and between waves, if web or search tools are available, actively look up existing solutions, competitors, failed attempts, market signals, relevant data. Report findings as evidence, cited and dated, graded per `fact-check.md`. If no search tools are available, list exactly what should be looked up and offer the user the queries.

## Question tracks

1. **The itch** — what problem does this scratch, who has it, and what do they do about it TODAY? If the answer is "nothing", that's a red flag, not an opportunity: why do they tolerate it?
2. **Prior art** (researcher hat) — who has built this or something adjacent? Why did the dead ones die? What niche do the alive ones leave uncovered? "Nobody's done this" almost always means "I haven't looked" — look.
3. **The delta** — versus the best existing alternative, what's 10x better, for whom? A 20% improvement is a feature, not an idea.
4. **Demand signals** — what evidence exists that anyone wants this: searches, complaints, workarounds, money already spent on inferior solutions? (researcher hat: find them)
5. **Feasibility floor** — what's the hardest technical or operational part, and has anyone demonstrated it's possible?
6. **The author-market fit** — why is THIS user positioned to do it: access, skills, distribution, obsession? What's missing?
7. **Kill criteria** — agree UPFRONT what evidence would kill the idea. An idea without kill criteria is a belief, not a hypothesis.
8. **The cheapest test** — design the smallest, fastest, cheapest experiment that hits a kill criterion or a green light. Days not months, conversations not code where possible.

## Super-level document checklist

- Any written description of the idea (notes, deck, landing page draft)
- Conversations with potential users (notes, transcripts, survey results)
- Evidence of spend on the problem today (invoices, tools in use, workarounds documented)
- Prior attempts by the user or their team
- Skills and assets inventory (what the user already has access to)

Suggested stages for `super`: (0) recon report with prior-art map; (1) the itch and the delta; (2) demand signals, requires user conversations; (3) feasibility and author-market fit; (4) kill criteria and cheapest test.

## Output

Brief = validation report: idea in one sentence, prior-art map (cited), the delta claim, demand evidence found vs missing, kill criteria, the cheapest-test plan (what, cost, deadline, what result means go/kill), and an honest verdict: pursue / test first / drop — with the reason.
Handoff offer: turn the cheapest test into a concrete plan; or escalate to the `fund` lens if this is an investment candidate.
